RedShadow findings and retests

Every finding goes from first note to verified fix. Nothing closes until a tester has retested it.

  1. Record it. Severity from a CVSS vector, evidence, proof of concept and notes.
  2. Assign it. A remediation owner gets a fix date set by severity.
  3. Fix it. The owner updates status and submits it for verification.
  4. Retest it. A named assessor records pass or fail in a retest round.

RedShadow roles and access

Four built-in roles. Everyone sees only the engagements and findings they are allowed to.

RedShadow reports and CSV import

Hand the client a finished PDF, and bring findings in from any spreadsheet.

  1. Report styles. Your logo, accent colour and sections, in client and internal editions.
  2. CSV import. Map columns, preview, catch duplicates, import in one safe transaction.
  3. Assets by name, IP or URL. Rows match the in-scope assets of the engagement.

Access control and audit log

Permissions are enforced by the server, and every change is recorded.

  1. Server-side permissions. Roles and per-engagement scope are enforced by the API, not the screen.
  2. Hash-chained audit log. Append-only entries with a built-in integrity check.
  3. Two-step sign-in. TOTP required by role, Argon2 passwords and lockout.

Install RedShadow

One command starts Docker Compose with PostgreSQL and Redis included.

Terminal
$ git clone https://github.com/TheShadowConn/RedShadow.git
$ cd RedShadow
$ docker compose up --build -d --wait
$ docker compose logs migrate | grep -A3 "FIRST LOGIN"
# the first admin password is printed once
# then open https://localhost and sign in
  1. Clone and start. Migrations run on their own and your data stays in named volumes.
  2. Sign in. Use the one-time admin password, then set your own and enrol two-step sign-in.
